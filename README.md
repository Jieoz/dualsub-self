# MyDualsub · 双语字幕（自带翻译 API）

在 **YouTube** 上叠加显示**双语字幕**（英文原文一行 + 中文译文一行）的 Manifest V3 浏览器扩展。

它仿照商业扩展 **Dualsub** 的架构，但有一个关键区别：

> **翻译不经过任何自建服务端 / API-Key 计费体系，而是直连你自己的 OpenAI 兼容翻译 API。**

如果你受够了某些扩展"每小时要去网站重新领 key"，这个项目就是为你做的——把翻译后端做成你自己填的三个变量（Base URL / Key / Model），密钥只存在你本地浏览器里。

---

## 支持站点

- `https://www.youtube.com/*`（桌面网页版）
- `https://m.youtube.com/*`（移动网页版，尽力支持）

> 目前只做 YouTube。架构上 main.js 负责站点适配，后续可扩展其它站点。

## 安装（加载已解压的扩展程序）

当前版本：**v0.7.6**。可从 [GitHub Releases](https://github.com/Jieoz/dualsub-self/releases/tag/v0.7.6) 下载 Chrome MV3 安装包。

v0.7.6 的主要变化（**字幕之间没有停顿** —— 整段连成一片，没有呼吸感）：
- **实测渲染层 439 个相邻单元里 436 个空隙为 0ms。** 上一条字幕消失的同一毫秒下一条就出现，说话人明明停顿了，字幕却一直连着。
- **根因是数据缺失被静默填补，而不是某处算错。** YouTube json3 里每个词（seg）只有 `tOffsetMs`（词的**开始**时刻），**没有任何词级时长字段**。解析器只能把一个词的结束时间填成下一个词的开始时间 —— 于是相邻词永远零间隔，说话人的停顿被吞进了前一个词的显示时长里。
- **但停顿信息确实在数据里**：同一 event 内相邻词的开口间隔中位 241ms，其中有 **500 处 ≥500ms、114 处 ≥1000ms**，那些就是真实的停顿。修复在渲染层按「末词说完即止」把多出来的静音让回去。
- **判据必须落在末词上，不能按整个单元均摊。** 停顿发生在最后一个词说完**之后**，而长单元的整体时长常常并不宽裕 —— 按均摊算只能保住 49% 的真实停顿（实测），按末词算保住 **99%**。
- **阈值取自实测而非拍脑袋**：源 token 相邻间隔 = 真实说话速度，中位 241ms/词、p75 400ms、p90 640ms；而渲染单元时长是中位 498ms/词。取 p75 的 **400ms/词** 作为说话上界，高出的部分即静音。
- **三条硬契约一个都没破**：`startMs` 零改动（出现时刻是唯一必须精确贴合音轨的量）、canonical token 跨度零改动、无重叠、无低于可读下限的单元。
- 真实轨验证：真实停顿保住率 **49% → 99%**（ASR 轨 185/186、波兰语人工轨 14/14）。新增门禁按「源轨里说话人真停了的位置，渲染层是否也有空隙」断言，去掉修复或改回均摊时分别精确变红（0% / 49%）。

v0.7.5 的主要变化（**非英语字幕轨整轨失效** —— 波兰语等语言原文缺字母、行超长、大面积 `[未翻译]`）：
- **根因不是一个 bug，而是整条链路里散落的"源语言是英文"假设。** 用户实测视频（波兰语人工字幕轨）138 个单元里 **127 条 `[未翻译]`**，原文肉眼可见缺字母：`najsłodszych księżyców` 显示成 `najs odszych ksi yc w`。逐层查出 5 处各自独立的 ASCII-only 实现：
  1. **分词正则**是 `[A-Za-z0-9]`，带变音符号的词在变音字母处断开、该字母被当分隔符丢掉。连带后果是词数被高估 → 长度上限失效 → 行超长 → 超过翻译层 14 词上限被 fail-closed 拒成 `[未翻译]`。
  2. **对齐用的词键**是 `[^0-9a-z一-鿿]`，把变音字母当标点从词首尾削掉（`Łódź` → `d`，纯变音词直接变空串）→ 显示流与 canonical 流对不上，**整轨抛错**。这是大面积未翻译的主因。
  3. **单条超长源 cue 无人拆分**：`maxWords` 只作跨 cue 合并判据。人工字幕一条 cue 就是一整句长文本，17 词整条原样上屏。
  4. **连写文字（中/日/泰/老/高棉/缅）按空白数词恒为 1**，所有长度上限对它们完全失效（实测 92 字日文、125 字泰文、45 字中文全挤成一行）。改为一字一词，下游 `maxWords`、token 跨度时间、去重对齐无需任何"如果是中日泰就特殊处理"的分支即原样生效。
  5. **`sanitizeSubtitleLine` 的白名单只保留汉字**，于是译文里一切拉丁字母被删 —— 产品把已经译好的内容抹掉了：`嗨 Vsauce 我是 Michael` → `嗨，，我是`，`Mimas`、`SodaStream` 全部消失。这一条**与源语言无关，英文轨同样中招**。
- **「模型没翻译」改为显式判定。** 上面第 5 条的删拉丁行为，本意是拦住"模型原样回吐源文"，但那是用副作用当判定。现由 `validateChineseDisplayUnit` 按「中文单位 vs 外文词」的比例显式判断（`no-chinese` / `mostly-untranslated`），sanitize 只负责剔除控制字符。计量必须按**词**而不是字符：按字符算会让 `嗨 Vsauce 我是 Michael` 的汉字占比只有 3/16，把完全正确的译文误杀。
- **翻译超时 20s → 90s，且收敛为单一常量。** 实测同网关同模型翻 4 行波兰语端到端 **10.0s–32.4s**，慢的请求被自己的 20s 超时掐断、重试再超时 → 整个 clip 全成 `[未翻译]`。这是大面积未翻译的第二个独立根因，同样与语言无关。原先 `20000` 在 4 处各写一遍，现统一为 `Core.TRANSLATE_TIMEOUT_MS`。
- **真实轨验证**（波兰语人工字幕轨，真实模型 gpt-5.4-mini）：超 14 词单元 **0** 个、变音字母 129/142 单元保住、翻译 **20/20 无 `[未翻译]`**、`嗨，Vsauce，我是Michael` 专有名词完整。
- **新增语言无关性门禁**：14 种书写系统（英/波/俄/希腊/阿拉伯/希伯来/印地/土耳其/越南/韩/日/中/泰/中英混排）各自走完整链路，断言对齐不抛错、不丢词、不超宽、零重叠、**原文逐字保真**；外加 `test/fixtures/youtube-manual-polish-raw.json`（yt-dlp 抓取的真实波兰语轨，**0% 词级时间** —— 与既有 ASR fixture 是两种不同形状，此前这一整类缺陷无法被发现）。5 处修复逐个反向注入，均精确变红。

v0.7.4 的主要变化（修复 v0.7.3 引入的整轨时间漂移 —— 字幕整体比音频晚约 2 秒）：
- **v0.7.3 是一次回归，v0.7.4 覆盖它**：v0.7.3 为消除重叠在 canonical 层"按词序前推"（`startMs = max(自身, 上一个词的 endMs)`）。前推让时间凭空增加且**永不归还**，于是整轨累积漂移。用同一视频前后两次实测导出逐条比对：**434 条字幕起始时间变晚，中位 +1961ms，最差 +10010ms**，且漂移随播放推进越来越大（前段 +1.6s → 末段 +2.2s）；同时 **53 个单元被挤到 400ms 以下**（最短仅 240ms，一闪而过）。实际体验就是「完全对不上原始音频」。
- **正确契约：`startMs` 一个都不许动。** 出现时刻是唯一必须精确贴合音轨的量，任何改动都会累积。「按词数重新锚定」同样不行（实测仍在累积：1441ms → 2080ms）。重叠改为只在渲染层把上一条的 `endMs` 截到下一条的 `startMs`，漂移严格为 **0**；重叠区内单元变短，由既有的 `padShortUnitsIntoSilence` 补进真实静音。
- 收敛位置从 `buildCanonicalTokenTimeline` 移到渲染层 `clampOverlappingRenderUnits`。canonical 层不能动时间：它与 token 跨度之间有 `validateTokenSpanCoverage` 的 fail-closed 契约；且 token 时间的重叠是 `appendTimelineTokens` 判定滚动重复词的**唯一依据**，抹平会让同一句话被渲染两次。
- 真实轨验证（4070 token / 439 单元）：起始时间**零漂移**（4070 个 token 无一被改动）、重叠 **233 → 0**、0ms 单元 0 个、词数守恒、最短单元 **240ms → 1199ms**。
- **新增真实数据门禁**：`test/fixtures/youtube-json3-rolling-raw.json` 是 yt-dlp 直接抓取的线上原始 json3（未经任何整理，解析走产品自己的 `parseJson3`）。此前三个版本连续修错的根本原因是验证数据里没有这个形状 —— 手造的 4 条 cue 样本规模太小，累积漂移要走过几百条才显形。门禁同时断言两个方向（零重叠 + 零漂移），退回 v0.7.3 前推实现时精确变红（真实轨抓出 1385 个 token 漂移）。

v0.7.3 的主要变化（修复滚动窗口 ASR 轨的字幕重叠 —— 这是「长句显示混乱」的真实根因）：
> ⚠️ v0.7.3 虽然消除了重叠，但引入了整轨约 2 秒的时间漂移，已由 v0.7.4 修复。请直接使用 v0.7.5。
- **半数字幕互相重叠、最多 3 条同时上屏**：YouTube 自动字幕是滚动窗口轨，相邻 cue 大幅重叠，同一句话在连续几条里反复出现。`cleanupCues` 只把 cue 外层 `end` 压到下一条 `start`，但真正拿去渲染的是 **token 跨度**，token 原生时间没被收敛，重叠原封不动回到渲染层。实测真实轨 439 个单元里 **233 个（53%）与下一条重叠**，重叠中位 2479ms、最长 10010ms，同一时刻最多 3 条字幕叠在一起。
- 修复落在 `buildCanonicalTokenTimeline`：canonical token 流是唯一权威时间源，在生成 fingerprint 之前收敛为严格单调不重叠。收敛用**按词序前推**而不是把前一条的 `end` 压到后一条的 `start` —— 后者在嵌套窗口上会把整条单元压成 0ms（字幕根本不显示）。
- 真实轨验证：重叠 **233 → 0**，同时在屏 **3 → 1** 条，0ms 单元 0 个，词数守恒。
- 新增 fixture `test/fixtures/youtube-rolling-window-cues.json`（439 条真实滚动窗口轨），门禁复现重叠形状；退回未收敛实现立刻变红。

v0.7.2 的主要变化（新增「导出当前进度」诊断快照）：
- 弹窗「导出字幕（SRT）」区新增 **导出当前进度（诊断用）** 按钮：按**当前已翻译的内容**原样导出，**不发起任何翻译请求、不产生任何费用**。
- 未翻译的单元保留原文并显式标记 `[未翻译]`，不会静默留空冒充成品。
- 文件头写入诊断统计：单元总数 / 已译 / 未译、每词时长中位与 p10、`<150ms/词` 的单元个数及最差样本原文。反馈显示问题时把这个文件发出来即可，无需口述症状。
- **成品导出的 fail-closed 契约完全不变**：原「导出 SRT」按钮仍然只要有一个单元缺译文就拒绝出文件，绝不产出半英文半中文的成品。诊断导出是**另一条独立路径**，两者共用同一个 SRT 渲染核心。

v0.7.1 的主要变化（字幕轨加载失败不再永久放弃）：
- **一次抖动就再也没有字幕**：YouTube 在限流/降级时会返回 `200` + 合法 JSON，但 `events` 为空（有时整个响应只有 `pens`/`wsWinStyles`），解析结果就是 0 条 cue。旧代码遇到这种响应只打印一行 `[dualsub] 解析后无有效字幕` 就 `return` —— 整条轨永久失效，用户看到「没有字幕」，且无从判断是扩展坏了还是网络问题，只能手动切换轨道自救。
- 空轨、HTTP 错误、网络/解析异常现在统一视为**瞬态故障**并重试，间隔 800ms → 2000ms → 5000ms；只有全部用尽后才记录并上报失败原因，不再静默放弃。
- 重试受 `timelineEpoch` + 轨道 URL 双重保护：换轨、换视频、关闭扩展会立即取消待执行的重试，陈旧响应不会打到新时间轴上。
- 门禁新增两个真实浏览器场景：`empty-track-retry`（空轨 → 重试 → 拿到真轨 → 正常渲染 59 帧）与 `empty-track-exhaust`（持续空轨 → 恰好 3 次重试 → 上报失败且不误绘字幕）。故障注入退回旧行为时，门禁会精确报出 `[dualsub] 解析后无有效字幕`。

v0.7.0 的主要变化（**修在根上**：源轨时间失真）：
- v0.6.8/v0.6.9 都只在**呈现层**给屏补时长，是治症状。真正的根在更上游：YouTube ASR 给出的 cue 自报时间本身是失真的 —— 例如 `[40322-41322]` 声称 13 个词只用 1000ms（**77ms/词 ≈ 650 wpm**），而它后面紧跟着 **1002ms 静音**。真机轨共 **9 条**这样的 cue，白白空着的静音合计 **6919ms**。
- 为什么呈现层补不干净：cue 的 `[start,end]` 是词级时间均摊的**唯一依据**，cue 被压缩 → 它切出的每一屏 `startMs`/`endMs` 全都是错的。而 ① 错的 `startMs` 靠延长屏尾永远修不回来；② 一条 cue 切成多屏时，可借的静音在**最后一屏之后**，中间那些屏与下一屏 gap 为 0，无处可借 —— 实测那条 95ms/词 的屏正是如此，v0.6.9 对它无能为力。
- 现在在 `buildCanonicalTokenTimeline` 建立 canonical 时间轴**之前**修复失真 cue：把 end 延伸进它后面的真实静音，延到按 200ms/词 勉强读得完为止，绝不越过下一条 cue 的 start，只动 end 不动 start（出现时刻仍严格来自源轨），带原生词级时间的 cue 完全不碰。
- 效果（真机轨 449 屏）：每词 < 150ms 的屏 **1 → 0**，最差 95ms/词 → **154ms/词**，重叠 0、覆盖 4070/4070。呈现层的可读时长补偿保留，作为静音不足时的兜底。
- 真实链路复验（gpt-5.4-mini）：24/24 单元，零空译文、零超长。



v0.6.9 的主要变化（可读时长下限改为随词数增长）：
- **长句仍会一闪而过**：v0.6.8 的可读下限是个**定值** 1200ms —— 1 个词和 13 个词拿到同样的时间预算。实测真机轨里 ASR 自己就会给出 `13 词 / 1000ms`（**77ms/词**，约 650 wpm，没人这么说话）这种明显失真的 cue，定值下限认为它「够长」于是完全不管，长句照旧来不及看。真机轨共 **9 条**原始 cue 的每词时长低于 150ms。
- 下限现改为 `max(1200ms, 词数 × 200ms)`。200ms/词 约合 300 wpm，作为「勉强读得完」的地板；该轨正常语速中位约 350ms/词、p10 约 255ms/词，所以正常语速的行**完全不受影响**，只有明显偏快的才补。
- 效果（真机轨 449 单元）：每词 < 150ms 的单元 **15 → 1**，最差从 92ms/词 提升到 154ms/词；用户报告的那句 `I think it's fair to say...`（13 词）从 1200ms 补到 **2002ms**。重叠 0、`startMs` 挪动 0、覆盖 4070/4070 —— 与 v0.6.8 相同的四条硬约束全部保持。
- 剩下 1 条无法改善：它后面没有静音，说话人紧接着继续讲。



v0.6.8 的主要变化（修复短句一闪而过）：
- **过短的字幕不再几乎看不见**：显示单元的时间此前完全照抄自身 token 跨度，**没有任何可读下限**。实测真机轨 449 个单元中有 **63 个短于 1200ms，最短仅 113ms**（单词 `I`）—— 长句在句中被切开后的后半截尤其容易只分到极短跨度，导致后半段几乎来不及看。现在过短单元会向后延长到 1200ms，但**只吃掉与下一条之间真正的静音**：绝不与下一条重叠、绝不改动 `startMs`（出现时刻必须仍精确对齐语音）、绝不改动 token 跨度。真机轨效果：短于 1200ms 的单元 63 → **40**，最短时长 113ms → **306ms**，重叠 0、`startMs` 挪动 0、覆盖 4070/4070。
- 剩下的 40 条受静音量限制：说话人紧接着继续讲，再延长就会和下一条抢位，属于物理上无法改善的情况。
- **补偿落在呈现层而非 canonical 层**：`units` 是 canonical provenance，`validateTokenSpanCoverage` 明确要求其时间与 token 跨度逐一相等（`source timing mismatch`），是刻意的 fail-closed 契约。补时长只作用于真正拿去画的 `renderUnits`。我最初改错了层，7 个既有测试立刻变红 —— 那 7 个测试是对的。



v0.6.7 的主要变化（修复译文被误判违规 + 字幕跟随视频时间）：
- **修复正确译文被判违规、整段回退英文**：分屏器会**故意**在句中切开（一屏最多约 12 词），这种单元的忠实译文本来就该断在逗号上。但校验规则不看原文、一律拒绝逗号结尾，于是 `If you're a human person,` → `如果你是人类，` 这种完全正确的译文被判违规。更深一层的原因是 `parseTranslationCoverageResponse` 重建校验单元时**把 `sourceText` 字段丢掉了**，所以校验侧就算想对照原文也永远拿到 `undefined`，只能按「整句结尾」严格判。现在判据改为「这一屏是不是整句的结尾」：句子仍在继续时跳过尾部形态检查，整句到此为止却断在逗号/连词上时照旧拒绝。实测 gpt-5.4-mini 首个 clip 3 行中有 2 行被误杀（3/3 复现），修复后 5/5 通过；4 clip / 24 单元真实链路零回退英文。
- **字幕出现时刻改为跟随视频帧**：渲染此前用固定 250ms `setInterval` 轮询，与视频时间无关，导致每条字幕平均晚 **127ms**、最坏晚 **248ms** 才出现（实测 449 个单元中 17.8% 晚于 200ms），且时长不足一个 tick 的短单元会被整条跳过（实测 5 条 < 250ms 完全不显示）。现改为 `requestVideoFrameCallback`（与画面同步，精度约 1 帧）驱动，不可用时退回 `requestAnimationFrame`，两者都没有才用定时器兜底。低配机上这两个回调会随浏览器降帧一起降频，页面隐藏时浏览器自动暂停，占用不高于原来的固定轮询。
- **补上对应门禁**：新增 2 个测试锁定「句中切开的译文不判违规」与「覆盖响应解析保留 `sourceText`」，并逐个做故障注入自检 —— 校验规则退回不看原文时 2 个测试变红，只丢 `sourceText` 字段时 1 个变红。

关于**字幕看起来一条紧接一条**：这是预期行为。实测原始轨相邻间隙中位仅 120ms、分段后 240ms，人眼几乎无感；而在真实停顿处字幕间隙（如 524ms）实际**长于**静音时长（404ms），24 处真实停顿全部正常消隐。看起来密是因为 449 个单元里有 425 个结束于语流中间 —— 说话人本身在连续讲话。

v0.6.6 的主要变化（修复整轨字幕完全不显示，含英文原文）：
- **修复连字符复合词导致整轨字幕消失**：字幕轨里只要出现 `purpose-built`、`old-fashioned`、`plug-in` 这类连字符复合词，整条字幕轨就加载失败，**连英文原文也一起不显示**，界面只报「解析后无有效字幕」。根因是全项目有**三份互相矛盾的「什么算一个词」正则**：`parseJson3` 与 `restoredBoundaryMarks` 各自手写了不含连字符的版本，而权威的 `RESTORE_WORD_RE` 含连字符 —— 于是 `purpose-built` 在词级时间轴侧被切成 2 个 token、在显示侧只算 1 个词，两条词流从该词起**永久错位**，最终对齐时抛 `display cue does not align to canonical timeline`。现在收敛为单一权威定义 `newWordRe()`，任何切词处不得再手写正则。
- **修复长 cue 大重叠时对齐失败**：重复接缝的回看范围此前写死为常量 32。但 YouTube 滚动 ASR 的重发前缀长度是由**单条 cue 的词数**决定的：一条 cue 长 40 词、重发前缀 35 词时，同一个词的上次出现距离可达 36 > 32，回看窗口看不见它就判不出是重复，同样抛对齐失败。实测 seg40/ov35、seg60/ov50、seg80/ov70 均崩，而 seg40/ov20 正常。现改为**随数据自适应**：回看范围 = 最长一条 display cue 的词数（重发前缀不可能超过它），既不会因常量偏小而漏判，也不会无界放大到把正文里合法的同词复现误判成重复。
- **补上能捕获这两类回归的门禁**：此前 210 个测试全绿却漏掉，因为测试 fixture **没有 `tokens` 字段**，从未走过词级时间那条真正会崩的路径。新增 3 个测试直接构造带词级时间的滚动 ASR，覆盖连字符复合词与大重叠两种输入，并逐个做故障注入自检 —— 退回旧正则时报「连字符复合词被拆开了」，退回常量 32 时报「大重叠下词流覆盖不完整」，确认门禁真的会变红。

v0.6.5 的主要变化（修复 v0.6.4 设置页无法操作）：
- **修复设置面板整体塌缩、任何设置都改不了**：v0.6.4 的设置页写了 `html,body{height:100%}`，但 Chrome 扩展弹窗的高度是**由内容反推**的，不存在预先给定的视口高度 —— 父级高度未定时百分比高度解析为 0，弹窗 `body` 高度塌缩成 0px，滚动区随之拿到 0 高度，再叠加 `overflow:hidden` 就把面板锁死：只看到两个分区标题，控件既不可见也不可滚动。现在弹窗高度由内容自然决定、只对滚动区设上限，实测面板 597px、滚动区可视 500px（内容 725px），全部关键控件可操作。
- **补上能捕获这类回归的门禁**：此前的弹窗测试只验证 SRT 导出的确认/进度/取消，从不检查控件是否真的可见可操作；而在普通浏览器标签里视口高度是确定的，`height:100%` 能正常解析，用固定视口测弹窗等于先给了 Chrome 不会给的条件。新门禁把设置页放进**高度不受约束**的 iframe 复现弹窗特有条件，断言面板未塌缩、6 个关键控件可操作、全部分区展开后不超出 600px 上限，并内置故障注入自检（退回 v0.6.4 写法时门禁必须变红，实测报「滚动区塌缩：可视高 18px」）。

v0.6.4 的主要变化（设置页布局重排）：
- **常用设置零滚动可达**：此前 6 个分区、32 个控件在 340px 宽的弹窗里全部平铺，页面高 1598px，而 Chrome 弹窗最大高度只有 600px —— 要滚 2.7 屏才能看完；「保存设置」在页尾 1598px 处，改个字号也得滚一趟才能保存。现在改为三段式布局：顶栏（标题 + 启用开关）、唯一滚动区、底栏（保存按钮常驻），**页面高降到 822px**，首屏即可操作启用开关、API 三项、测试连接、字号、底部间距、原文/译文颜色、显示原文行、译文在上，保存按钮在任意滚动位置都能点。
- **按使用频率分层**：字幕外观里的常调项（字号、间距、双色、原文行、上下顺序）默认展开；高级样式（字重、字体、描边、阴影）、加载与节奏、源语言与译文语言、导出 SRT、配置备份与旧兼容项收进 5 个默认折叠的分组。此前「显示」区独占 520px/14 个控件，把每次要碰的字号和设一次就不动的描边颜色混在一起；「字幕节奏」区 2/3 是自陈「当前不参与主路径」的旧兼容项却占着显眼位置。
- 纯布局改动，不涉及任何配置读写逻辑：设置项全部按 ID 取值，已核对 35 个控件 ID 与类型零缺失、零变更。

v0.6.3 的主要变化（整轨语义分屏真正跑通 + 省 27% token）：
- **修复整轨语义恢复在长视频上完全失效**：分屏器内部按「词」计算并返回边界标记，但整个系统的标记契约是「每个 token 一个标记」。ASR 的一个 token 可能含多个词（`1,800`、`334,720`、`8.8` 这类带千分位/小数的数字），词数 ≠ token 数，导致标记数组被越界写入撑长、长度校验失败直接返回空 —— **25 分钟真实字幕轨此前输出 0 屏，整轨语义分屏全废**。现在分屏器全程在 token 空间工作（屏长按屏内各 token 的词数之和度量，切点只落在 token 之间），返回长度恒等于 token 数。
- **修复分屏质量退化成机械均匀硬切**：模型只输出屏边界、从不输出句末句号，而超长修复此前按句号分句，于是整轨 4000 词被当成**一个巨句** —— 任何一处漏切都会触发整段重排，把模型给出的上百个自然边界全部抹平。实测退化成 95% 的屏正好 10 词、89% 切在句子中间（如 `you're` / `going` 被切开）。现在修复单位改为「屏」，只重切真正超长的那一屏，其余模型边界原样保留：均匀 10 词屏占比从 95% 降到 17%，屏长回到 1–12 的自然分布。
- **词数计量与屏上所见一致**：`1,800`、`8.8`、`purpose-built` 都计为一个词（此前数字被算成 2 词，会让一个显示 12 词的合格屏被算成 13 词而误触发超长抛错，随机拖垮整轨）。
- **省 27% token、快 41%**：语义分块参数从 `chunk 120 / overlap 30`（25% 重叠 = 33% 额外输入）调整为 `chunk 200 / overlap 20`。25 分钟真实轨实测：请求 80→50 次、token 116816→85267、耗时 1055s→620s，分屏质量还略有提升。参数收敛为 `core.js` 中的单一权威常量，缓存键与实际调用共用，避免参数漂移导致缓存永久失效。
- **补真实长轨回归门禁**：此前的离线样本每个 token 恰好 1 词、强制补句末句号、全是 20 词单句，真实长轨的特征一个都没覆盖，两轮 bug 全部逃过门禁。新增确定性门禁复刻「多词 token + 无句末标点 + 长连续语流」三特征，并用故障注入验证过它能抓到上述两个 bug（不消耗真实 token）。

v0.6.2 的主要变化：
- **修复首屏中文字幕卡顿（可达 1 分钟）**：整轨语义恢复的模型请求此前绕过全局并发闸门直连模型端点，与首屏 fallback 翻译抢占同一 API，导致首个中文被挤到 429 退避队尾。现在整轨恢复统一走 `ensureGate()` 且用最低优先级（0），首屏 fallback（100）/预取（20）/导出（1）全部抢先，语义恢复只用富余容量，绝不拖慢首屏。慢/失败的语义恢复不再让中文字幕空等。
- **修复成组丢句**：运行时翻译此前是 clip 级 all-or-nothing——clip 内任一 cue 译文不合规就整组作废回退英文。现在运行时 coverage 校验支持逐 cue 容错（`lenient` 模式）：单句坏译文只回退那一句英文，同 clip 其余照显中文；结构性协议漂移仍整包 fail-closed。**导出 SRT 路径保持严格 fail-closed，成品绝不半英文半中文。**

v0.6.0 的主要变化：
- 英文、顺序和词级时间统一来自不可变 canonical token timeline；模型只能返回 token 边界 ID，不能回显或改写英文。
- 翻译响应改为严格的 unit/span coverage JSON；缺项、重复、错 span、空译文或旧结果全部 fail-closed，不再依靠 `cold kettle` 等短语特判搬移中文。
- 当前播放段拥有最高调度优先级；全轨 SRT 必须明确确认费用，后台按最多 8 个 source units 批处理，并显示进度、Token 和取消按钮。
- 配置、轨道或视频变化会主动取消旧请求；stale 结果不能写 cache、usage、snapshot、state 或 DOM。

### 翻译 API（OpenAI 兼容）—— 核心三件套

- **API Key**：`Bearer` 鉴权用的 key。

## 翻译质量：canonical token timeline + 严格 coverage

v0.6.0 将英文事实、边界决策和中文翻译拆成三个互不越权的层：

1. **Canonical token timeline**：本地从字幕轨道建立稳定 token ID、原文、顺序和 timing；滚动 ASR 重叠也在这一层压成无重叠词流。后续 renderer、seek、cache 和 SRT 都读取同一 immutable `TimelineSnapshot`。
2. **结构化边界规划**：语义模型只能返回 `{"cutsAfter":["token-id"]}`。本地拒绝未知、重复、乱序或额外字段，再从 canonical tokens 重建英文；正常恢复和 oversize rescue 都没有自由英文回显后门。
3. **结构化翻译 coverage**：翻译模型只返回 `{unitId, coverFrom, coverTo, translation}`。本地要求每个 unit/span 恰好覆盖一次、顺序和指纹一致、译文非空；任一错误整包拒绝，不安装或缓存半成品。
4. **不可变提交**：resegment 和 translation 都创建新 snapshot revision，旧 snapshot 不原地修改。异步等待后会重新检查 video、track、source language、API Base、model、target language、prompt、generation 和 AbortSignal。
5. **快速 fallback**：semantic 尚未完成时只服务当前播放段；若恢复慢或失败，当前段立即使用 fallback translation，不让中文字幕等待 1–2 分钟。semantic 只有在实时播放位置的译文准备好后才原子接管。
6. **舒适短屏**：semantic 以 10 词为舒适目标、12 词为硬上限；fallback 只有为保全自然短语时才可放宽到 14 词。没有安全边界时显式回退，绝不硬切悬空冠词、介词、助动词、短语动词、比较结构或名词短语。
7. **缓存隔离**：翻译缓存 namespace 为 `dsc-v70`，身份包含 endpoint、model、target language、prompt/contract、segmentation mode 和 source fingerprint；语义恢复缓存同时绑定严格词流，不复用旧协议结果。
8. **中文显示清洗**：简体中文译文移除中文句号 `。`，保留逗号、问号、感叹号、数字和必要标点。清洗只在当前受支持的 `zh-Hans` 目标上运行。

首包默认最多等待 8 秒：扩展只会暂停自己触发的播放，翻译就绪或超时后自动继续；切视频、禁用或运行时重建也会解除这次暂停。

### 原文断句：ASR 语义重组

YouTube 自动字幕（ASR）的事件是按滚动时间片切的：一句话常被切进多个事件，相邻事件还会重叠（后一个含前一个的尾词）。直接每个事件当一条字幕会导致原文断句凌乱、出现 `work work under` 这类重复词。

没有可用原生 token 时间时，解析后仍由 `core.js` 的 `resegmentCues` 做保守 ASR 重组：

- 合并间隙很小（< 300ms）且上一句未自然结束（无句末标点）的连续碎片，时间轴取并集。
- **最小词数合并（`minWords`，默认 3）**：即便遇到句末标点，若当前段词数不足 `minWords`，也优先与下一条相邻 cue 黏合，避免 "OK." "Right." 这类碎句单独成段；只有合并会超上限（`maxWords` / `maxDur`）或间隙过大时才单独成段。配合上限切句，分段长短更均匀。
- 去掉相邻事件的**滚动重叠词**（按词比对，忽略大小写/标点），避免重复。
- 按句末标点 / 最大时长（~6s）/ 默认目标最大词数（12）重新切句；语法未完成尾部只可受限续接到 14 词。

### 字幕节奏：句间空隙 + 自然分行

ASR 滚动事件几乎每条都与下一条时间重叠，`resegmentCues` 去重叠时会把前句 `end` 精确压到后句 `start`，于是连续语流的句单元首尾相接、间隙恒为 0，字幕像一堵「墙」永不消隐；而 LLM 又常把多行 ASR 合并成超长完整句（实测 6 行 → 一句 78 字占屏 5.4s），整句堆 3–4 行盖住画面。v0.4.0 用尾缩 + 模型自然分行专门修这两类节奏问题：

- **句间尾缩（`tailTrimMs`，默认 120ms）**：对每个输出句单元的 `end` 做一个小的视觉回缩，让「原本紧贴」的句子之间也出现 ~120ms 断点，字幕该消隐时能消隐。仅当 `duration > tailTrimMs*2` 时才缩（短句不缩，避免缩没），缩后保证 `end - start ≥ 300ms`、绝不 `end < start`；**真停顿（本就有间隙）不受影响**，只缩本句尾不动下一句 `start`。`tailTrimMs = 0` 完全关闭（向后兼容）。
- **译文 1:1 对齐**：模型按 unit ID/token span 返回结构化 coverage；每个中英文单元共享同一起止时间，renderer 与 SRT 读取同一个 snapshot fingerprint。`maxCharsPerScreen` / `maxDurPerScreen` 仅保留旧配置 round-trip。
- 「句间空隙」仍在 popup「字幕节奏」区可调；单屏字数/时长控件仅作旧配置兼容提示。

### 边播边翻：预取 + 并发 gate + 缓存

- **整 clip 一次请求**：semantic 与恢复失败后的 `fallback-translation` 模式都按 clip 调用 `translateClipLines`；纯 fallback 仅在后台语义恢复尚未结束时暂显英文，不重复抢占请求。
- **clip 按 cue 边界切**（默认目标 ~12s/clip，v0.4.1）：绝不在句子中间断、clip 之间不重叠不重复，同时让单次 prompt 更短、延迟更稳。
- **分级优先预取**：当前播放段拥有最高优先级；临近段尾的下一段次之；普通预取更低；显式全轨 SRT 后台批次最低。高优先级请求可越过已排队的后台任务。拖动进度条停稳后立即翻目标 clip，预取与渲染保持解耦。
- **加载态**：semantic 某句译文还没到时，按需显示轻量"翻译中…"（半透明斜体，可在设置里关）。原文照常显示，译文到了平滑补上，不闪烁。

### 低配电脑运行占用优化

为让插件在低配机上也轻量，运行时做了以下优化（在不牺牲上面"预取/加载速度"的前提下）：

- **单一节流渲染循环**：去掉了原来 `timeupdate` 事件 + `setInterval` 的双触发，改为单个 ~250ms 的节流循环。**当前时间对应的 cue 没变化时直接 return**，不做任何查找/DOM 写入——长视频持续播放时，idle（字幕未切换）期间主线程几乎零工作，只有 cue 切换那一刻才写一次 DOM。
- **二分查找当前 cue**：cue 按时间有序，用 O(log n) 二分 + "上次命中下标"提示，连续播放时大多数 tick 退化为 O(1)，不再每帧线性扫整段字幕。
- **预取与渲染解耦**：预取单独降频到 ~1s 检查一次，不再绑在高频渲染 tick 上。
- **空闲零开销**：视频**暂停 / 播放结束 / 标签页切到后台**时，渲染与预取循环都会停掉；切回前台或继续播放再恢复。**未启用扩展时彻底无定时器/监听器在跑**。
- **完整生命周期管理**：所有定时器 id 与事件监听器都登记在册；切视频（SPA 路由变化）、更换 `<video>` 元素、禁用扩展时统一 `teardown`（清定时器 + 解绑监听 + 移除渲染器），杜绝累积泄漏。
- **进度条拖动防抖**：seek 过程中不逐个中间位置触发翻译/预取，停稳 ~350ms 后才翻目标 clip 一次。
- **全屏/影院模式跟随**：渲染器作为播放器子节点随容器自动重定位；若被播放器 DOM 重建踢出，渲染 tick 会以 O(1) 的 `isConnected` 检查发现并重新挂载。

### Token 优化与持久缓存

- **翻译持久缓存**：每个 clip 使用独立 storage entry，key 绑定视频、轨道、源语言、API endpoint、模型、目标语言、prompt/coverage contract、segmentation mode、source fingerprint 和 clip span。写入带 generation marker；写入期间身份失效会只回滚本次 entry，不覆盖其它标签页的新值。重看、拖回或刷新命中同身份缓存时零翻译调用。
- **语义恢复持久缓存（v0.5.10）**：严格词流验收通过后，将整轨语义 cue 以独立 `dss-v1` namespace 缓存；key 同时绑定视频、轨道、网关、模型、恢复 prompt 和源 token 文本/时间指纹。刷新或切回同一视频时会再次验证缓存词流与源 token 完全等价，再直接复用，避免长视频重复执行约 100 次整轨断句请求。独立 LRU 最多保留 24 条语义轨道。
- **提交后 Token 计数**：供应商返回的 OpenAI-compatible `usage` 先暂存；只有 coverage、代际、cache 和 snapshot 提交全部成功后才累计。stale、aborted 或验证失败的响应不污染当前页面统计。
- **失败重试调度（v0.3.0）**：某 clip 翻译失败标记为可重试态，由一个后台调度器按指数退避（默认 base 2s / max 30s）**自动反复重翻**，直到成功；连续失败达上限（默认 6 次）才转为「翻译失败」终态并在 UI 上明确标示（而非静默当原文）。全部 clip 翻译完成时调度器自动停转，不空转烧 CPU。
- **请求超时**：单次翻译请求加 `AbortController` 超时（默认 20s）。网关无响应时按失败兜底（显原文）+ 退避，不会让 clip 永久挂起占着并发位。
- **结构化短协议 + `reasoning_effort=low`**：边界调用只返回 token cuts，翻译调用只返回 coverage JSON；后台全轨准备最多把 8 个 source units 合成一批，减少重复固定 prompt。
- **旧批处理参数兼容保留**：`batchLines`、`contextLines`、`sentencePrompt`、`maxCharsPerScreen`、`maxDurPerScreen` 仍可随配置导入导出 round-trip，但 v0.4.0 主路径不再使用它们。

### 配置导入 / 导出

设置面板的"配置备份"区可把当前配置**导出**为 JSON 文件，换机器 / 重装扩展时**导入**即可，免去重填 API 配置。

> **安全提示**：默认导出**不包含 API Key**；只有用户显式勾选“包含 API Key”时才写入凭据。含凭据文件请勿分享或上传。导入后点“保存设置”才会生效。

### 导出双语 SRT 字幕

播放时可把当前视频的双语字幕**导出为标准 SRT 文件**（`buildSrt` + `formatSrtTime`），三种排版任选：

| 模式 | 说明 |
| --- | --- |
| `bilingual_orig_top` | 原文在上、译文在下 |
| `bilingual_trans_top` | 译文在上、原文在下 |
| `only_translated` | 仅译文（导出前要求全部字幕单元已有译文，不再用英文补空槽） |

时间戳为标准 `HH:MM:SS,mmm`，按起始时间升序、跳过空单元，可直接喂给任意播放器 / 剪辑软件。只要有原文单元缺少译文就拒绝生成，绝不输出半英文半中文成品。

若全轨尚未翻完，popup 会先显示缺失单元数并明确确认可能产生的 API/Token 费用；确认后才以最低优先级、最多 8 个 source units 一批准备剩余轨道。界面显示单元/批次/Token 进度，可随时取消后续批次；只有 snapshot coverage 达到 100% 后才下载 SRT。

## 架构说明

```
manifest.json   扩展声明（MV3）
main.js         world: MAIN —— 访问页面 #movie_player，抓字幕轨道
core.js         纯逻辑（解析/清洗/语义重组/semantic unit 1:1 翻译/时间轴/clip 切分/缓存/退避），无浏览器依赖，可 Node 单测
isolated.js     world: ISOLATED —— 拉字幕、调翻译 API、预取+全局并发 gate+缓存、渲染叠加层、读写 storage、与 popup 通信
popup.html/js   设置 UI（直接从 storage 读配置回显，引入 core.js 复用默认配置/颜色校验）
icons/          占位图标
test/           离线测试（node 直接跑）
```

- **双脚本 + 自建 RPC**：`main.js`（MAIN world，能访问 YouTube 播放器私有对象但不能用 `chrome.*`）与 `isolated.js`（ISOLATED world，能用 `chrome.storage`/`chrome.runtime`）通过一条固定随机字符串常量的 `CustomEvent` 通道通信，兼容 Firefox `cloneInto`。
- **轨道抓取**：main.js 每 3 秒轮询 `#movie_player`，读 `getVideoData().video_id` 与 `getAudioTrack().captionTracks`。**关键：必须等轨道 URL 带上 `pot` 签名参数后才算有效**，否则字幕请求 403；给 URL 设 `fmt=json3` + `c=WEB`（移动端 `MWEB`）。SPA 路由变化靠轮询 `location.search` 的 `v` 检测。
- **渲染**：`.dualsub-renderer` 挂到 `.html5-video-player`，监听 `<video>` 的 `timeupdate`，按 `currentTime*1000` 查当前 cue。样式用 CSS 变量控制。

## 安全说明（请务必阅读）

- 你的 **API Key 只存在你本地浏览器的 `chrome.storage.local`**，不会上传到任何第三方服务器。
- 翻译请求**只发往你自己填写的 API Base URL**，不发往其它任何端点。扩展全部对外请求只有两类：① 拉取当前 YouTube 视频的字幕轨道（YouTube 自身的 URL）；② 把字幕发往你配置的翻译 API。**无任何遥测 / 埋点 / 数据上报**（源码可审计，全文仅两处 `fetch`）。
- 为了让扩展能直连你填写的**任意** API 端点（地址运行时才知道），manifest 申请了 `<all_urls>` 的 `host_permissions`。这是实现"自带翻译 API"所必需的——但请知悉：技术上扩展因此具备访问任意站点的能力。**本扩展只在你触发翻译/测试时向你配置的端点发请求，源码开放可自行审计。** 如需更克制的权限模型，见 `FEEDBACK_TO_UPSTREAM.md` 中的备选方案。
- 不要把真实 key 提交进 git（`.gitignore` 已排除常见密钥文件）。

## 已知限制

- 移动端 `m.youtube.com` 的播放器对象结构未经真机验证，按桌面端同套逻辑尽力支持。
- CI 会在 Chromium 中运行生产 `core.js` / `isolated.js` 的冻结 fixture 回放，并真实点击 popup 的全轨确认、进度、导出和取消流程；第三方 YouTube 页面本身的 `pot` 签名和站点 DOM 变化仍属于现场集成风险。
- **自适应并发限流（v0.3.0）**：全局并发上限默认 4，gate 感知 429 / 超时——遇限流即把并发**减半收缩**（4→2→1，下限 1）并进入冷却窗,连续成功一段时间后**逐级恢复**到上限。从源头减少把网关打爆导致的整段断供，比静态并发更稳。
- **Coverage 失败关闭（v0.6.0）**：unit/span 缺失、重复、越界、错序或空译文都不接受部分结果；该 clip 保持原文显示，并由统一退避调度整包重试。
- `resegmentCues` 的滚动重叠去重是**词级**比对，对英文等空格分词语言效果好；对中日韩等无空格语言，ASR 重叠本就少见，按整条事件处理。
- 持久缓存按 `videoId+轨道+语言+模型+clip起点` 为 key；切换模型/译文语言会按新 key 重翻（旧缓存自然不命中，并按 LRU 逐步淘汰）。
- 当前只支持 OpenAI 兼容的 `/chat/completions` 接口。
